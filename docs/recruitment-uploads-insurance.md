# 徵人照片與勞健保截圖

此功能在 CompanyBrain，沒有更動獨立 HumanResourceManagement 專案。

## 操作

- 徵人 → 應徵者 → 履歷表，可多選圖片／PDF，或反覆按「拍照追加」保存正反面。每份上限12MB；逐份上傳，單份失敗不會中止其他檔案。
- 員工 → 證件文件同樣支援多檔與拍照追加。
- 每份文件有「移除」。移除後停止提供預覽、隱藏文件、略過待確認辨識，掃描不會復活；NAS原檔及已確認人事資料保留，操作有日誌。
- 證件號碼不強制台灣身分證格式或檢查碼，支援居留證等號碼；既有加密儲存方式維持。
- 員工 → 證件文件 → 勞健保異動：上傳截圖或PDF；使用現有Gemini設定產生待核對卡。可分別填加保生效日、到職日、退保生效日、離職日，並選勞保／健保／勞健保。只有按確認才寫入；空白到離職欄位保留原值。
- 到離職日期可在基本資料修改；保險生效日可在勞健保紀錄按「修改日期」。加保與退保分開紀錄，重複確認會拒絕。
- 辨識不把申報日、收件日、截圖日期當生效日，也不以加退保日推測到離職日。看不清楚的日期留空，人工補填。

## NAS儲存與部署

預設使用既有 `NAS_RESUME_PATH` 掛載下的 `勞健保異動/` 子資料夾；首次上傳建立資料夾，不必改compose或既有設定。容器帳號需對原履歷資料夾有寫入權限。備份時包含該子資料夾。

程式支援 `NAS_INSURANCE_PATH` 自訂位置；若要使用，需由部署設定將該環境變數及NAS目錄掛載傳入容器。沒有設定Gemini時仍會保存檔案，畫面會提醒改用人工新增保險紀錄／修改員工日期。

部署前備份資料庫。將此分支的應用程式檔案更新到既有CompanyBrain目錄，保留NAS上的 `settings.env`、`.env`、`compose.yaml` 和所有資料，再使用既有 `scripts/apply.sh` 重建。啟動會新增 `hr_documents.removed_at` 欄位，不刪除既有資料。

目前的 `scripts/nas-auto-deploy.py` 白名單沒有包含HR檔案；僅推GitHub不會自動套用本次HR修改。需要更新應用程式檔案並重建容器，單純restart不足。

## 驗證範圍

整合測試使用隔離的PGlite與暫存文件資料夾，驗證多檔保存、移除後預覽404、掃描不復活、證件號碼加密、辨識確認、日期修正及重複確認防護。Gemini使用測試替身，尚未用公司真實截圖驗證辨識準確度，也未連線或修改正式NAS。
